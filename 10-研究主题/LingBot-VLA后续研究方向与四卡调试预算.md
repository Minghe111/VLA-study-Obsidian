# LingBot-VLA 后续研究方向与四卡调试预算

> [!abstract] 建议
> 延续 MICA 的语言约束研究，优先研究执行过程中的约束保持、双臂分工与指令纠正；先用小任务集定位失败，再决定是否引入 RL。以下是文献支持的研究建议，尚未经过本项目实验验证。

## 候选方向及最小验证

| 优先级 | 研究问题 | 最小实验与关键对照 | 成本与创新边界 |
| --- | --- | --- | --- |
| 1 | 语言约束能否在执行期间持续生效：指定左右手、操作顺序、禁止接触；中途指令变化后及时纠正 | 选择 3–5 个双臂任务，同一初始场景构造不同指令及对应有效轨迹，划分未见约束组合。比较原始 SFT、等数据量反事实 SFT、约束方法；配对评测相同初始种子 | 适合延续 MICA；单纯增强语言权重或增加去语言分支已有相关研究，需要证明时序约束与双臂角色上的增益 |
| 2 | 利用未来表征预测风险，决定何时重新观察、缩短执行长度或重规划 | 先比较固定执行长度 5/10/25/50；再以模型预测的未来特征预测接触违规、臂间冲突或失败风险。风险标签来自实际 rollout；比较相同推理预算下的 RTC/自适应长度方案 | 初期以评测和小预测头为主。未来 query 不是现成的可靠风险分数，不能使用真实未来观测作为在线输入；自适应动作块本身不是新问题 |
| 3 | 小规模约束 RL 与失败恢复：任务完成率提高时能否同时减少违规 | 从同一 SFT 检查点比较 SFT、SFT+RL、约束 SFT、约束 SFT+RL；限定少量任务与交互预算，使用仿真可核实的接触/目标/顺序判据 | 成本包括策略推理、仿真采样和参数更新。先确认动作相关的训练信号，再增加模块或损失；不能仅凭训练 loss 判断改进 |
| 4 | RM65-B 双灵巧手的少示范迁移与缺视角鲁棒性 | 接口稳定后比较手部协同控制与独立有效控制维度，在多个示范预算及未见物体上评测；相机输入严格按实物安装状态记录 | 仅完成 URDF 或动作维度映射属于适配；研究贡献需要少数据迁移、泛化或鲁棒性证据。硬件现状以资源卡及最新部署记录为准 |

共同指标：任务完成率、全部试验上的约束违规率、同时成功且无违规的比例、指令变化后的反应时间、恢复成功率以及端到端 p50/p95 延迟。明确每个指标的分母；增加训练数据、参数或推理次数时须设置等预算对照。

## 文献核查与差异化要求

以下于 2026-10-02 核查，均为作者文献或官方仓库报告，非本机复现。

- [LingBot-VLA 2.0 官方仓库](https://github.com/Robbyant/lingbot-vla-v2)：已有 MoE 动作专家和当前/未来 query 教师特征监督。因此新增 MoE 或未来预测模块不能直接视为本项目创新。
- [CAG / LIBERO-CF](https://arxiv.org/abs/2602.17659) 与 [CofactVLA](https://arxiv.org/abs/2608.04396)：已研究视觉捷径、反事实指令及语言去混杂。我们的候选切入点应落在执行期间的约束保持、动态纠正、双臂角色组合，仍须通过实验检验差异是否成立。
- [RTC](https://arxiv.org/abs/2506.07339) 与 [GeoAAC](https://arxiv.org/abs/2609.20776)：实时动作块执行和自适应执行长度已有工作。风险触发重规划需与这些方法及固定长度基线比较，控制推理预算。
- [Acting While Understanding](https://arxiv.org/abs/2606.15285)：语义与动作异步解耦也已有研究，不能把一般的慢语义/快控制直接作为新意。
- [RLinf LingBot 示例](https://rlinf.readthedocs.io/en/latest/rst_source/examples/embodied/lingbotvla.html) 当前介绍的是 LingBot-VLA-4B、Qwen2.5-VL-3B 主干的 SFT/GRPO 路线；不能当作 LingBot-VLA 2.0 6B/Qwen3 已可直接使用的 RL 训练接口。

## 四卡是否支撑调试

2026-10-02 已复核 166 为 8×RTX 3090，每卡 24 GiB；161 的 8×RTX A6000、约 48 GiB/卡来自 2026-09-20 的历史实测，本次认证未通过，未刷新该机器状态。四卡微调运行尚未定位，因此没有实际训练天数、峰值显存或每步耗时。详见 [[2026-10-02-LingBot微调状态核查]]。

四卡 3090 可作为小规模或部分参数训练的候选资源，但完整 6B 学生、教师分支、优化器及激活是否装得下必须测量；4×24 GiB 不等于单卡可用 96 GiB。已有 [[LingBot-VLA训练核心参数-冻结VLM冒烟配置]] 只能证明配置存在，不能证明训练已通过。关闭教师监督的简化实验须单列，不能称作完整方法复现。

建议将迭代分成三档：

1. **20–100 步调试**：单任务、micro batch 1 起步，记录模块冻结、教师开关、精度、梯度累积和分片方式；核实前反向、保存与恢复。
2. **1000–3000 步筛选**：固定小任务集和评测种子，判断约束指标是否改善；该步数是工程筛选预算，不是已证明充分收敛的配置。
3. **正式训练**：仅对有效候选按一致训练与评测预算开展多种子实验，不把每次代码调试都扩展为 50 任务完整训练。

设稳定每步耗时为 t 秒、更新次数 N，则纯更新耗时约为 N×t/3600 小时，另计初始化、保存、评测及重启开销。若整个有效运行始终占用四张卡，GPU 天数为四倍有效运行小时数除以 24；不能将进程停止后的空闲时间计入。中断续训需逐段累计，并单列重跑的失败尝试。

官方仓库于 2026-09-22 发布 Distributed Muon，并展示 H20 上的优化器吞吐比较。这是后续可评估的工程选项，其速度不能直接套用到本机 3090，也不能假设 9 月 20 日部署的代码已包含该实现。

### 1. 本次结论与依据

**主推方向：面向语言约束的双臂 VLA 闭环控制。** 建议题目：

> 面向语言约束的双臂机器人视觉语言动作控制方法研究

开题汇报时用一句话限定问题：**研究双臂机器人如何在连续执行和指令更新过程中，保持尚未解除的手臂分工、操作顺序及禁触要求，并在偏差出现时纠正行为。**

### 2. 为什么优先这一方向

**研究积累连续。** 已有讨论和笔记持续关注语言约束，可以把问题从“语言有没有影响动作”推进到“要求在不同任务阶段如何持续有效”。但与 MICA 原稿的差异仍须拿原文逐项核对。

**硬件能够形成有意义的研究情境。** 双臂协作有单臂任务中不明显的依赖：一侧保持支撑时，另一侧才能操作；更新右手目标，不应顺带解除左手责任。灵巧手可以先使用少量可重复的抓握姿态，研究贡献不依赖首先解决复杂指内操作。

**可以形成可证伪的问题。** 同样的图像和任务终点，允许的中间动作会随角色、顺序、历史和新指令变化。可以通过配对场景检查方法是否真正使用了这些信息。

**能够分阶段交付。** 约束评测、持续遵循方法、动态纠错与小规模真机验证之间有清楚的依赖。即使完整在线 RL 成本过高，前两项仍可独立验证，不会使全部工作停在训练系统建设上。

### 3. 用一个具体例子解释研究问题

初始指令：**“左手扶住容器，右手把红块放进去，全程不要碰蓝块。”** 在右手尚未抓取时，用户补充：**“改放到旁边的托盘，左手继续扶住容器，其余要求不变。”**

需要分别判断：右手的目标是否更新；左手的保持要求是否保留；蓝块禁触是否仍有效；原来排队的动作是否继续被错误执行。初期更新时刻限定在可行阶段，并明确更新语义，不制造物理上无法满足的要求。

这个例子只是实验设计。真实任务应选择头部视角可观测、对象不易遮挡、抓握可重复的场景；如果“扶住”无法可靠判定，可先用“左手将容器保持在指定区域”这样的可测条件替代。

### 4. 两项递进研究，而不是两个互不相关的模型

#### 研究一：任务阶段驱动的语言约束持续遵循

核心问题：**同一个约束在什么时候生效、什么时候完成、什么时候允许解除？模型能否把这种状态用于动作生成？**

建议先覆盖三类明确可判定的条件：手臂角色、阶段先后关系、指定对象禁触。固定自然语言表达范围与合法组合，从训练数据中记录相关事件和有效轨迹。

候选方法是维护一个小型约束状态，包含当前对象绑定、左右臂角色、阶段进度和仍有效的条件，再通过轻量条件模块或适配器影响动作策略。状态可由观测、机器人反馈与短历史估计；如果先使用人工标注或仿真真值，只能作为监督或上界，不能混入部署输入后声称已完成感知闭环。

**待检验假设 H1：** 显式维护与动作相关的约束状态，比只重复原始语言、堆历史帧或增加同量反事实数据，更能提高未见约束组合上的合规完成率。

这不是已确定的新算法。有限状态机、已有约束表示和简单条件化都是必要强基线；如简单方法同样有效，应据此调整方法贡献，而不是增加结构复杂度。

#### 研究二：增量指令下的约束保持与执行纠错

核心问题：**新指令只修改任务的一部分时，如何保留其他仍有效的要求，并从正在执行的状态继续？**

建议明确区分追加、替换、解除三种更新，记录指令版本及其生效时刻。模型应识别哪些动作仍合法、哪些待执行动作已过时，以及当前双臂状态允许怎样过渡。初期仅处理语义明确且物理可行的更新，不要求解决任意自然语言冲突。

工程上要先统一动作队列、指令刷新和观测时间戳。清除过时命令与重新调用模型是基础对照，不能单独包装为算法创新。拟研究的增量状态更新和纠错学习，需证明它们在相同刷新频率与时间预算下仍有额外收益。

**待检验假设 H2：** 显式区分“被修改的要求”和“仍需保持的要求”，并学习可行过渡，可以减少指令更新后的旧约束丢失，同时控制响应延迟和任务耗时。

如需增强策略，可先收集失败与纠正轨迹进行监督学习；只有已经出现可重复的控制瓶颈，再比较约束 RL 或局部技能改进。人类纠正后只做 SFT 不称为 RL。

| [GeoAAC](https://arxiv.org/abs/2609.20776) | 基于去噪轨迹几何自适应执行长度；作者标注投稿 ICRA 2027 | 投稿不等于录用；自适应长度需与已有方法及等频率对照比较 |
| [LIBERO-MAX](https://arxiv.org/abs/2609.36518) | 固定初态、种子和事件前动作的中途环境变化配对评测 | 可借鉴事件前一致的评测设计；它不是现成的双臂语言约束 benchmark |

**候选差异化落点是：双臂协作中，增量语言更新后仍有效的约束怎样被表示、保持，并影响当前动作及过渡。** 目前这是值得验证的切入点，不是已经证实无人研究的结论。如果 SwitchVLA、Logic-VLA 或其他工作已完整覆盖同一机制与协议，需要继续缩小问题或换切入点。

### 7. 最小实验与避免误判的对照

建议第一批选 **3–5 个任务**，同场景构造可行的角色、顺序与禁触变化，划分未见约束组合；新增文本必须对应有效而不同的动作要求，不能只给旧轨迹换一句冲突指令。

比较顺序：普通 SFT → 等数据量反事实/约束 SFT → 显式规则状态机或阶段提示 → 候选约束状态方法 → 增量纠错。相关近邻如 CAG、SwitchVLA、Logic-VLA 按方法兼容性选择直接复现或清楚标注的受控改编；不能默认不同本体代码可直接复用。

关键控制条件：同一初态、训练数据量、动作接口、最大时长、重试次数和推理预算；动态实验固定事件前历史，单独控制新指令到达时刻。测试组合应在所有训练和数据生成环节中留出。

| 指标 | 统计定义与作用 |
| --- | --- |
| 完整任务成功率 | 完成任务的回合数 / 全部有效回合数 |
| 合规完成率 | 完成且未违反本次有效约束的回合数 / 全部有效回合数 |
| 约束违规率 | 出现至少一次违规的回合数 / 全部有效回合数；按角色、顺序、禁触拆分 |
| 更新后旧约束保持率 | 在更新后仍保持全部未解除要求的回合数 / 存在该类更新的有效回合数 |
| 纠正延迟与更新后成功率 | 新指令到达至首次正确响应的时间；无响应另报并计入失败，不能仅统计成功响应样本 |
| 完成时间与执行代价 | 检查收益是否主要来自停顿、更频繁查询或无限重试 |

应在多个随机种子和独立初态上给出样本数与不确定性。不可逆违规发生后，即使后续恢复到正确终点，也不能把整个回合重新计为无违规。

### 8. 开题前后建议的八周验证窗口

这是建议的先导实验安排，具体取决于导师要求与实际剩余学制。

| 阶段 | 应交付什么 | 收缩或调整条件 |
| --- | --- | --- |
| 第 1–2 周 | 精读最接近的工作与 MICA 原稿；建立一个基座的可复查闭环；选定约束判据 | 若主要问题是接口或示范质量，先修复，暂不增加模型模块 |
| 第 3–4 周 | 3–5 个任务的配对失败案例；普通 SFT、等量数据与规则基线 | 若强基线已基本解决所定义问题，重新选择更有研究价值且可观测的条件 |
| 第 5–6 周 | 第一项方法消融；检查约束状态是否确实影响动作 | 若收益完全由额外数据/推理预算解释，不将其记为方法改进 |
| 第 7–8 周 | 动态更新小实验、首个可重复真机任务或已明确的适配差距 | 若动态图谱过宽，先固定角色和一种更新类型，保住核心问题 |

硕士论文可按“背景与问题 → 约束评测与数据 → 过程约束方法 → 增量纠错方法 → 真机验证”组织。评测与平台是研究支撑，不能仅靠目录安排就视为多个独立创新点。具体学位要求以导师与学院规定为准。
