# VLA 基座选择：InternVLA-A1.5、π0.5 与 GR00T N1.7

> [!abstract] 阅读后的选型建议
> [Analysis] 如果目标是尽快建立可反复调试的语言条件动作基线，优先验证 **π0.5 在官方 JAX 框架中的 LoRA／分片微调路径**；如果重点是语义保持、未来表征与执行约束，**InternVLA-A1.5 是值得重点考察的研究候选**；如果重点是人类视频迁移、跨本体和完整部署工具链，考察 **GR00T N1.7**，但其当前默认训练资源需求超过单张 3090 的显存。
> 这是根据公开方法和实现提出的投入顺序，尚无本项目统一训练、成功率或 GPU 天数支持最终换基座。已有 LingBot-VLA 2.0 决策与历史实验保留，后续是否更换以同协议小规模试验为依据。

## 2. 三个模型分别解决什么问题

| 比较项 | InternVLA-A1.5 | π0.5 | GR00T N1.7 |
| --- | --- | --- | --- |
| 核心问题 | 将理解、未来动态监督和连续动作联合训练时，怎样保留原 VLM 语义并减少目标干扰 | 怎样让机器人在新家庭、新物体和长任务中利用网络语义与异构机器人经验 | 怎样统一不同机器人与人类操作中的表示，并提供可后训练和部署的通用策略 |
| 视觉语言骨干 | Qwen3.5-2B 原生 VLM；轻量 unified expert | PaliGemma 系列视觉语言骨干与约300M连续动作专家；具体阶段见精读 | 当前 N1.7 使用 Cosmos-Reason2-2B / Qwen3-VL；N1 祖先论文中的 Eagle 不能套到当前版本 |
| 动作生成 | 连续 flow matching 动作块 | 离散 FAST 学习与连续 flow action expert 按阶段配合；公开微调主要是连续 flow | flow-matching DiT 连续动作块；延续 System 2语义、System 1动作的架构分工 |
| 语义学习入口 | 原生 VQA、子任务预测、FAST相关监督 | 异构 co-training、高层子任务和低层动作；KI版本通过语言/离散动作监督更新骨干 | 当前视频语言骨干加机器人动作后训练；人类视频的迁移表示是重要升级 |
| 未来信息怎样进入训练 | foresight tokens 查询未来信息；冻结 WAN2.2-5B 提供训练监督 | 不以未来像素生成作为论文的核心方法；主要组织语义与动作数据 | N1 的合成数据与 N1.7 的人类视频预训练需要分版本解释 |
| 部署时的主要输出 | 连续动作；标准动作推理可略去视频分支 | 连续动作块；具体是否包含高层子任务循环要看部署实现 | 连续动作块，通过 Policy API、可选 TensorRT 等部署路径执行 |
| 我们应重点检查 | 预见监督真的帮助语言约束和纠错，还是只增加训练成本 | 公开微调是否损害已预训练的语义能力；高层语义链是否实际运行 | 自定义动作空间与预训练相对 EEF 表示之间的迁移是否有效 |

[Analysis] 三者都能作为视觉语言条件的连续动作策略候选，但其核心证据各不相同。A1.5 的训练期视频教师不能直接等同于部署期世界模型规划；π0.5 原论文展示的家庭长任务不能直接等同于 `pi05_base` 的默认服务器行为；N1.7 的 System 1/2 命名也不保证我们的接入具有两套独立、异步执行的控制循环。

出处：[A1.5论文](https://arxiv.org/abs/2607.04988)、[π0.5会议论文](https://proceedings.mlr.press/v305/black25a.html)、[N1.7固定版本说明](https://github.com/NVIDIA/Isaac-GR00T/blob/51d4c89f72fda44cbf77285c6a8114b52676b8a1/README.md)。模块、公式与实验定位见三份精读的第07–10节。

## 3. 训练梯度和推理开关，比模型名称更影响研究结论

### A1.5：冻结教师仍可能需要经过教师反向传播

[Analysis] WAN 教师的权重冻结，意味着不更新教师参数；学习 foresight conditioning 仍需要从视频损失沿教师的条件输入路径回传梯度。不能因为参数冻结就给整个教师路径包上 `no_grad()`，也不能只按部署用约2B骨干估算完整训练显存。详见 [[InternVLA-A1.5精读-理解与潜在预见统一基座#09 核心公式与符号]]。

[External] 当前官方 README 推荐真机动作推理使用 `config.inference_backend="optimized"` 和 `config.action_loss_only=True`，避免加载 WAN 视频分支。这个部署设置的意义是减少推理负担，不能直接充当完整预见监督训练的等价设置。[固定README](https://github.com/InternRobotics/InternVLA-A-series/blob/e6fc904f9edbfb14532e97095fc2372202517f76/README.md)

### π0.5：单向 attention 与知识隔离是不同机制

[Analysis] 骨干不读取连续动作 token，但动作专家仍读取骨干 K/V；这种前向单向依赖不能阻断 flow loss 回传骨干。后续 Knowledge Insulation 用显式停止部分梯度的路径，配合 FAST / 文本交叉熵更新骨干；这与原 π0.5 的多阶段数据和训练方法有关，但不能将两个来源写成同一篇论文中的同一机制。[Knowledge Insulation原论文](https://arxiv.org/abs/2505.23705)

[External] 当前 openpi 的 `pi05_base` 被作者说明为经过 KI 训练的权重；公开任务微调的 flow loss 路径并非完整复现 KI，也不自动包含原论文的高层子任务在线循环。因此实验要记录“权重从哪里来”和“本次更新了哪些梯度”，不能只记录模型名。[固定openpi README](https://github.com/Physical-Intelligence/openpi/blob/215abfb217dbac7d5f1273282331b9b1866c0479/README.md)

[External] **π0.5 的状态输入要单独验收。** 固定版本的 `pi05_libero` 配置关闭离散 state 输入，不能照抄后宣称 RM65 的24维状态仍进入模型。应检查实际 tokenizer 前缀与机器人转换器，验证 `discrete_state_input`、单位、归一化与左右通道顺序。详细固定代码证据见 π0.5 精读第07、13节。
### N1.7：代码默认配置与下载权重配置需要分别记录

[External] 固定 README 记录扩展的132维状态/动作容量和40步预测 horizon，但下载权重的层数、选取骨干层和精度等字段，可能与代码类的默认参数不同。记录所选 checkpoint 配置及入口覆盖后的最终运行配置；自定义本体的16步示例不是所有 N1.7 模型的统一预测长度。详见 [[GR00T N1.7精读-跨本体动作与人类视频预训练]]。

| π0.5 | 98.8 | 98.2 | 98.0 | 92.4 | 96.9 |

[Paper] 同一论文 RoboTwin Table 3 报 π0.5 clean 82.7、randomized 76.8、平均79.8；A1.5 为93.3、93.0、平均93.2，但该表没有 N1.7 行。A1.5 的 RoboTwin 后训练包含每任务50条clean + 500条randomized示范，共27500条，并使用100K更新，不能写成只训练clean后的随机场景零样本泛化。训练集、模型与执行长度差异见 A1.5 精读。[Paper: PDF p. 13, Table 3; PDF p. 24, Appendix A.2]

[Analysis] 原 π0.5 的新家庭任务、N1 的仿真/真机实验、N1.7 当前 README benchmark 和上述 LIBERO 汇表各有自己的评测单位。将这些不同来源的最高数值填成“总排名”会丢失任务难度、数据和预算信息。本项目最终排序需要自己的统一数据与闭环协议。

## 7. 一轮足以改变选择的小规模比较

[Hypothesis] 首先比较语言约束研究所需的最低能力，而非一次性复现三个模型的全部大规模预训练。

1. **统一原始数据与控制schema。** 选择3–5个可执行任务，固定当前单头RGB、24维控制、场景/物体划分。对镜像角色、操作顺序或禁止触碰构造不同语言条件；指令必须对应合法可区分的轨迹。
2. **分别建立可靠加载与微调基线。** A1.5从base、π0.5从pi05_base、N1.7从base+NEW_EMBODIMENT起步；记录任务专用权重是否额外含目标benchmark示范。接口回放、归一化往返和一次前后向通过后才扩大训练。
3. **配对闭环比较。** 每个候选使用相同初始种子、动作执行频率、最大episode时长、人工干预和重试预算。动作块预测长度与执行长度分别记录；先统一执行窗口，再测各模型推荐窗口。
4. **只对有效候选扩展。** 20–100步只检查可运行性；筛选训练用固定示范预算、独立验证集。正式比较再增加随机种子与评测次数，报告样本数和不确定性。

| 指标 | 定义/作用 |
| --- | --- |
| 完成率 | 完整完成任务的试验数/全部有效试验数 |
| 约束违规率 | 发生任一角色、顺序或禁触违规的试验数/全部有效试验数；不只统计成功回合 |
| 合规完成率 | 同时任务成功且无违规的试验数/全部有效试验数 |
| 指令纠正延迟 | 修改指令到动作/阶段响应的时间；固定修改时刻和执行队列策略 |
| 端到端p50/p95 | 包含预处理、通信、模型、动作排队，区别于模型forward时间 |
| 有效GPU小时 | 训练及评测的实际资源消耗，补充峰值显存与失败重跑 |

[Analysis] 若A1.5只在新增语义/预见训练后胜出，应通过同基座消融隔离收益；若π0.5语言能力在微调后下降，应比较冻结骨干、JAX LoRA与当前训练路径，而不先堆叠新损失；若N1.7关节微调表现不佳，应先检查本体/相对表示和示范覆盖，避免把接口问题归因模型质量。
