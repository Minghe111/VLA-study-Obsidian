# π0.5高层VLM开放数据接入：数据配方与能力验收

## 本次决策语境

用户提出：VLM能力微调应采用质量可靠、种类丰富的公开数据，组织方式参考π0.5、π0.6、π0.7。建议将公开视觉／视频监督作为下一阶段能力训练的主体，现有history3000保留为窄协议回归集；少量本体数据承担RM65-B域适配和动作保留。这里只制定方向与验收，未授权为某个推荐数据量启动训练。

保持同一π0.5共享VLM读取记忆、生成自然语言子任务的架构；READ／WRITE仍是本项目协议，子任务不恢复为固定库选择。RM65-B继续沿用SDK24 `[左臂6,左手6,右臂6,右手6]`、三RGB和60ms控制。外部数据保留其原始相机、时间和本体语义，不强行改写成这一合同。

既有审计显示：3000条训练行对应288个保存观察点、元数据记录的272组唯一三视角像素，只有49个不同目标字符串；标签主要可由task/history/memory规则决定。它们不等于3000条独立图文事实或成功轨迹。此处引用[[2026-10-21-RM65B高层SFT瓶颈诊断与π0.5官方训练对照]]中的已归档审计，本日未重新解码原图。训练内WRITE仍失败的问题需要单独诊断，不能承诺换大数据即自动修复。

## 1. Pi系列可借鉴的内容与公开边界

| 来源 | 作者公开的方法 | 本项目借鉴范围 |
| --- | --- | --- |
| π0.5 §IV | 多本体机器人、高层子任务、图文描述／问答／定位混合训练；网页源列举CapsFusion、COCO、Cambrian-7M、PixMo、VQAv2；高层根据观察与总任务预测语义子任务 | 借鉴真实观察与多种目标配对、任务混合及目标mask，不继续只扩大JSON模板 |
| π0.6模型卡 §2–3 | 延续异构数据，增加框／关键点预测和提示元数据；KI下文本／FAST监督VLM，连续FM监督动作专家并阻断FM回主干梯度 | 分开记录文本、离散动作、连续动作的标签及梯度；此次能力暖启动不因此自动包含FAST/FM训练 |
| π*0.6／RECAP | 真实尝试、失败和纠正产生回报、价值与优势条件，再改进策略 | 公开VQA没有轨迹回报时不构造虚假value或positive优势；RL阶段另行接入 |
| π0.7 §V–VI | 机器人、人类视频、web、旧策略及RL策略数据共同训练；提示包含总任务／子任务、目标图、质量／速度／错误段和控制模式；允许失败与次优数据 | “干净”指观察与标签可靠、来源可追溯，不能等同于全成功；已知结果及事后标签不能偷偷进入在线actor输入 |

来源：[π0.5论文](https://arxiv.org/html/2504.16054v1)、[π0.6模型卡](https://website.pi-asset.com/pi06star/PI06_model_card.pdf)、[RECAP论文](https://arxiv.org/html/2511.14759v2)、[π0.7论文](https://arxiv.org/html/2604.15483v1)。π0.7于2026-04-16发布，真实存在；本次没有升级本地模型为π0.7。

[openpi README](https://github.com/Physical-Intelligence/openpi)本次读取仍只列π0、π0-FAST、π0.5，π0.5仅支持FM头训练／推理；没有据此获得完整高层／web训练管线。未找到可直接复用的完整π0.5／0.6／0.7内部训练数据包和全部配比；论文描述、权重发布、数据接口和完整训练资产必须分开。

[官方pi-data-sharing](https://github.com/Physical-Intelligence/pi-data-sharing)公开了真实的LeRobot共享／上传验证格式：`meta/info.json`的fps、`custom_metadata.csv`的episode_id／robot_id／station_id／success／is_eval_episode／checkpoint_path等字段、可选`custom_annotation.json`内的`start_time/end_time/label`区间。可借鉴episode身份和时间段标注；它不是三个模型完整内部训练格式，亦不意味着本项目要使用托管API或上传数据。

## 2. 推荐数据与各自能监督什么

| 数据 | 官方规模／标签性质 | 本项目用途及限制 |
| --- | --- | --- |
| GQA balanced | 全集约22M问题／113k图，另提供平衡子集；基于清理后的Visual Genome人标场景图程序生成问答，含属性、关系、语义程序 | 属性、关系和组合条件；程序生成不等于逐题人工核验，优先筛选室内物体与可见关系 |
| RefCOCO／RefCOCO+ | 各约142k指代表达／20k图，人类指称游戏标注并关联目标对象／框 | 同类干扰物中的目标绑定；+限制位置词，故左右关系训练需保留RefCOCO或其他来源 |
| VQAv2 | train443,757问／82,783图；每问10个人类回答，并提供同问异图异答案的互补图像对 | 视觉问答、颜色／数量／对象识别；筛回答一致样本，保留互补图对检验视觉依赖 |
| RoboVQA | 829,502视频文本对、29,520独特指令；机器人、人和带工具的人，238h；任务含规划、成功判断、可供性、过去描述与未来预测 | 比单张VQA更贴近历史理解、阶段判断和下一步推理；保持原任务类别、视频时间边界和标签来源，不把预测当已发生事实 |
| Bridge V2＋ECoT（备选） | Bridge V2有60,096轨迹／24环境；ECoT在其250万以上transitions上合成推理文本 | 提供机器人图像与子任务候选。ECoT利用完整轨迹做事后教师解释，须筛除依赖不可见未来的目标；不能称人工逐帧真值 |
| DROID（域桥接候选） | 官方76k成功示范／350h／564场景，另发布失败轨迹；三相机、人类episode指令和机器人状态 | 真实机器人场景覆盖；没有现成逐步子任务／READ／WRITE标签，按episode指令做语义训练不能自动建立完成状态真值 |

来源：[GQA官网](https://cs.stanford.edu/people/dorarad/gqa/)、[RefCOCO作者论文](https://arxiv.org/html/1608.00272v2)与[数据API](https://github.com/lichengunc/refer)、[VQAv2官方字段与统计](https://visualqa.org/download.html)、[RoboVQA项目](https://robovqa.github.io/)与[代码／数据入口](https://github.com/google-deepmind/robovqa)、[Bridge V2](https://rail-berkeley.github.io/bridgedata/)、[ECoT](https://github.com/MichalZawalski/embodied-CoT)、[DROID](https://droid-dataset.github.io/)。这些是候选来源，不声称π0.5使用了表中每一种数据。

访问和许可分开核对：VQA标注为CC BY4.0、原COCO图片另按来源条款；RoboVQA README明确代码Apache2.0、其他材料CC BY4.0；GQA／RefCOCO不能把论文或代码许可当作全部数据许可，本轮尚未完成独立数据条款确认。RefCOCO旧下载入口有失效记录，正式准备时须记录实际镜像与hash。若需要许可说明和来源hash更明确的点定位备选，可评估[Ai2 PixMo-Points](https://huggingface.co/datasets/allenai/pixmo-points)：ODC-BY、含image_sha256，人标点不等于目标框或抓取位姿。

RoboVQA也需要语义筛选：[原论文](https://arxiv.org/html/2311.00899)以人工事后分段／描述为基础，自动派生QA，不是829,502条独立人审轨迹。首轮优先context planning、past description和经抽查的success；随机负例可供性不等于物理不可行，段落结束也不自动证明本项目成功条件。按[官方加载示例](https://github.com/google-deepmind/robovqa/blob/main/data_loading_and_eval.ipynb)先拆任务问答，再选指定任务，避免同一text记录中的其他答案进入prompt；规划输入截至决策时刻，未来步骤只作target。多个QA按源episode归组，缺原episode映射时保留官方split，不随机拆QA。

## 3. 本地建议格式：保留来源，再映射成prefix／target

以下为本项目拟议的统一中间层，不宣称是PI内部schema：

| 字段组 | 最低内容 |
| --- | --- |
| 来源 | dataset／version／license／sample_id／原image_id或episode_id／标注来源human、program或teacher |
| 观察 | 原始图像或视频引用、相机角色及有效mask、帧时间戳、可见证据区间；图像／视频hash |
| 条件 | task_type、总任务、截至t的history、可见memory；可选control_mode、带来源的元数据 |
| 监督 | answer、目标框／点、子任务文本或memory操作；每个字段的证据引用、有效性与可监督区间 |
| 可选机器人目标 | native embodiment／action_space／state／action_chunk／成功／回报／优势，分别有valid mask |
| 划分 | split_group、源场景／对象／episode身份；同源图或片段衍生的所有变体归同一split |

训练读出参考[Google官方PaliGemma说明](https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/paligemma/README.md)及[GQA transfer配置](https://github.com/google-research/big_vision/blob/main/big_vision/configs/proj/paligemma/transfers/gqa.py)：图像＋任务prompt是prefix，正确答案是suffix；监督target和EOS，prefix不计语言CE。保留当前模型tokenizer／读出映射，不能直接套另一聊天VLM的role模板或更换tokenizer。

不同任务保留其合适输出：VQA为答案，定位为有坐标约定的定位目标，子任务为自然语言，READ／WRITE才使用本项目JSON。允许统一容器，不把所有答案改造成同一种记忆JSON。

纯图文／视频没有动作时，action、FAST、value目标均无效；不能用全0的24维动作、success=false或advantage=positive补缺失标签。官方上传CSV面向有成功标签的机器人episode，普通VQA不强塞进该CSV。其他机器人动作保留原空间，当前阶段不用于RM65-B动作损失。缺相机用mask表达，不复制一张图假装三相机；外部视频保留原始fps，60ms只约束RM65-B执行。

## 4. 分阶段预算与训练范围建议

所有数量是本项目建议的试验预算，未证明为最小门槛，亦不是PI官方配比。

1. **数据试点**：先组成约2万条视觉问答／指称样本，目标覆盖至少1万独立图像，限制单图问句数；完成分层人工抽查、证据审核和跨源去重后才讨论启动。优先GQA／VQAv2及可核实许可、访问的RefCOCO子集。
2. **视觉语义扩展**：试点确有留出收益后，再考虑5万—10万条；按独立图像、对象、关系和问题类型报告，而非只报告行数。首轮继续语言全层attention LoRA，视觉塔与动作专家冻结；这能训练现有视觉特征的使用，不预先保证获得新物理技能。
3. **视频与高层**：另加入约1万—2万条RoboVQA时间窗口，按原episode归组、按语义任务均衡。需要连续视频证据的任务在视频MEM实际启用后验证；只取末帧的对照不能宣称训练了视频记忆。
4. **READ／WRITE与本体桥接**：以约1000—3000个有核验依据的独立决策点为候选预算，构造正确／过期／冲突／不可确认记忆，变体数另计。保留少量原history3000作协议回归，重新标清“指令已发出”与“物理阶段已完成”。公开数据没有现成READ／WRITE真值，需要本项目明确规则、证据并审核。
5. **动作保留与后续联合训练**：只对真实RM65-B数据做动作回归／教师保持，KV锚定作用域和权重单独对照，不直接把现有强锚套到所有新问答。冻结专家不能保证输出不变，因为它读取的VLM条件会变。FAST/KI联合动作学习与RECAP仍是后续独立阶段。

保持当前共享VLM架构：本轮若实施，答案／定位／子任务／记忆CE通过既有语言读出更新LoRA；视觉塔和连续专家不接收参数更新，动作回归约束可经冻结专家对VLM LoRA传梯度。推理动作仍由原专家生成，不以文字动作答案替代实际控制。视频MEM的新增视觉参数与视频目标在单独阶段开放，不能混同本轮冻结视觉的能力暖启动。

## 5. 数据质量与能力验收

- 每源保留原始文件、版本、许可、source ID与转换收据；抽查坏图、坐标变换、文字答案是否受图像支持。公开数据可复核，不代表无噪声。
- 按图像／episode／场景做split和跨源hash去重。GQA、RefCOCO、VQAv2共享COCO等图源，各自默认train/val不能自动保证混合后无泄漏。
- **静态视觉**：同问换图应按证据换答案；同图换目标／角色应响应；去图或错图对照结合原任务准确率分析，不能单凭掉分宣称grounding。
- **时序与记忆**：同末帧、不同历史需要不同答案；旧记忆与新可见证据冲突时纠错；证据不足允许未知。actor输入不含问题时刻之后帧，不把future prediction的答案改写成已经发生的事实。
- **动作与系统**：扩展原8例动作池到留出场景／指令，先同输入数值对照，再做匹配协议的无接管闭环；JSON／EOS、离线语义准确率与任务SR分别报告。数据增加不替代现存训练内WRITE失败的优化诊断。
- 预训练可能已见公开评测数据，故公开集增益仅作任务适应证据；本体留出场景、角色组合和独立时间片段评测用于验证项目收益。
