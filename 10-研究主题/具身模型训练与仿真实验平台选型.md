# 具身模型训练与仿真实验平台选型

关联：[[RM65-B双灵巧手：LingBot-VLA2选型与适配路线]]。

## 推荐决策

先以 RoboTwin 2.0 + XPolicyLab 做多基线训练入口与仿真评测；LingBot-VLA 2.0 优先走上游官方训练/评测代码，再接统一适配器。RL 阶段优先考察 RLinf；本机双灵巧手数字孪生单独选 ManiSkill 或 Isaac Lab。不要同时部署所有候选平台。

| 平台 | 最有价值的用途 | 边界 |
| --- | --- | --- |
| RoboTwin + XPolicyLab | 双臂基准、统一策略服务与评测接口、各模型训练包装 | 训练仍调用模型自身代码；目录存在不等于训练/评测全链路已验证 |
| RLinf | VLA 的 SFT、RL、rollout 与多卡资源协调 | 当前查到的 LingBot 文档是4B/Qwen2.5版本，不是2.0的6B/Qwen3版本 |
| ManiSkill | 操作任务、GPU并行仿真、自定义机器人 | RM65双臂双手、接触动力学、相机与任务均需配置验证 |
| Isaac Lab | 自定义机器人、灵巧手、RL与遥操作扩展 | 支持导入URDF不等于已支持所有VLA训练 |
| RoboVerse/MetaSim | 多仿真器与任务资产统一、跨仿真器研究 | 多一层集成，第一阶段不必引入；具体模型后端仍逐项核查 |
| AllenAI vla-evaluation-harness | 跨基准统一推理评测、训练期间调用评测 | 主要是评测层，不替代各模型优化器与训练实现 |

## 核查到的关键兼容性

- XPolicyLab 的 Pi_05 文档提供基于 openpi 的数据转换、训练和仿真评测路径。
- SmolVLA 文档提供 `lerobot-train` 微调及评测；数据使用 LeRobot v3.0，不能假设其他策略使用相同版本。
- 官方策略目录还列 ACT、GR00T_N17 和多个 WAM，但本次未逐个运行验证。
- `LingBot_VLA` 文档明确采用 Qwen2.5-VL-3B。不能将名称相似理解为兼容 LingBot-VLA 2.0。
- RLinf 的 LingBot 示例为 `lingbot-vla-4b`，配置动作维度14，并使用 RoboTwin 的 `RLinf_support` 分支。其 SFT/GRPO 路径可作为2.0迁移参考，但不能只替换权重路径。
- RoboTwin 新本体文档的夹爪配置以每侧一个主动关节和 mimic 联动为基础。双手各6个主动自由度需要扩展动作、控制和专家采集接口；导入URDF只解决一部分问题。

## 分阶段验收

1. 原版 RoboTwin 上用 ACT 或 SmolVLA 跑通单任务训练、加载检查点、仿真闭环和结果记录。
2. 用蚂蚁官方固定版本复现 LingBot2 的 RoboTwin 推理，再添加统一策略适配器，验证归一化、动作块、reset 与随机种子一致。
3. 保留原版基准作为论文可比结果；另建 RM65-B 双灵巧手三相机环境，标定关节耦合、摩擦、驱动与时延。
4. RLinf 先复现已支持模型的一个小任务，再迁移 LingBot2 的可训练路径；普通推理服务器只能返回动作，不能替代RL所需的梯度、采样和损失实现。

8×3090 初期按单任务测显存与吞吐，逐步增加并行数；不要预设8个大模型与8个渲染进程可同时驻留。训练和大规模评测分时运行，各模型独立环境，通过统一观测/动作协议对接。
