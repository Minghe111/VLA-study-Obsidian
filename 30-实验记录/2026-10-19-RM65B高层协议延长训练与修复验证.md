### 共用观察与记录结构

下面的READ、初始WRITE和左侧SUBTASK都来自`fresh_protocol_layout_01_left_31100`的`decision_step=0`，指向同一份NPZ。三种监督是在同一个静态观察点离线制作的，**不能拼称为策略已经在线完成READ→WRITE→执行的轨迹**。

实际NPZ字段已只读核对：

| 字段 | 实际shape／dtype | 用途 |
| --- | --- | --- |
| `full_image` | 480×640×3，uint8 | 全局RGB |
| `left_wrist_image` | 480×640×3，uint8 | 左腕RGB |
| `right_wrist_image` | 480×640×3，uint8 | 右腕RGB |
| `state` | 24，float32 | 实测SDK状态，顺序为左臂6／左手6／右臂6／右手6 |
| `instruction` | 标量Unicode字符串 | 环境指令；下面context另有显式goal |

JSONL只存`observation.npz_path`，像素和状态在NPZ中。读取后仍走既有预处理／归一化；24维、三RGB、60ms合同保持。当前标签没有逐步关节动作或action chunk监督。

```json
  },
  "context": {
    "catalogue": [
      {
        "description": "Last confirmed progress and unresolved requirements.",
        "slot_id": "current_progress"
      },
      {
        "description": "Observed original side and location of the sample.",
        "slot_id": "original_location"
      },
      {
        "description": "Observed identity and role of the requested sample.",
        "slot_id": "sample_identity"
      },
      {
        "description": "Observed verification status and evidence.",

      }

    "goal": "Verify the sample initially on the left and return it home, then verify the sample initially on the right and return it home.",
    "mode": "READ",
```

### WRITE：根据读出的旧记忆决定更新

真实sample_id：`fresh_protocol_layout_01_left_31100:d0:static_hold_protocol:WRITE`。其goal、catalogue、观察与上例相同，`mode`改为`WRITE`，新增／使用的实际输入字段为：

```json
{
  "read_ids": [
    "sample_identity"
  ],
  "selected_memory": [
    {
      "confirmed": false,
      "revision": 0,
      "slot_id": "sample_identity",
      "status": "empty",
      "value": null
    }
  ],
  "visible_history": []
}
```

对应`target_text`的JSON内容为：

```json
{
  "operations": [
    {
      "confirmed": true,
      "op": "WRITE",
      "slot_id": "sample_identity",
      "value": "The first requested sample is initially on the left."
    }
  ]
}
```

含义是向空槽写入“第一个要求处理的样本初始在左侧”。`confirmed=true`是这条记忆的标签状态，**不表示机械臂已经抓起、完成物理验证或任务成功**；这里监督的是目标／初始方位事实。

四种WRITE情况的真实示例摘要如下。KEEP来自右侧样本，CORRECT和EMPTY来自其他观察点；完整sample_id和原始context均在七条副本中，不把不同示例合成一条连续轨迹。

| 统计分支 | 该真实示例的旧槽位 | 精确监督文本 |
| --- | --- | --- |
| WRITE | status=empty，confirmed=false，revision=0，value=null | `{"operations":[{"confirmed":true,"op":"WRITE","slot_id":"sample_identity","value":"The first requested sample is initially on the left."}]}` |
| KEEP | status=active，confirmed=false，revision=2，value=The first requested sample is initially on the right. | `{"operations":[{"confirmed":true,"op":"KEEP","slot_id":"sample_identity"}]}` |
| CORRECT | status=active，confirmed=false，revision=4，value=The first requested sample is initially on the right. | `{"operations":[{"confirmed":true,"op":"CORRECT","slot_id":"sample_identity","value":"The first requested sample is initially on the left."}]}` |
| EMPTY | status=active，confirmed=true，revision=1，value=The first requested sample is initially on the left. | `{"operations":[]}` |

`KEEP`可将已有但未确认的同一事实确认；`CORRECT`纠正旧值；空`operations`表示不更新。协议中没有`{"op":"EMPTY"}`。表中的revision是实际历史数值，**不是应当根据数字选择操作的规则**；已验证的revision捷径及其局限见[[2026-10-19-RM65B-C2200留出绑定与仿真闭环验证#revision局部因果对照|局部因果对照]]。

左侧真实`target_text`：


### 这些样本怎样参与训练

`图像＋实测state＋mode／goal／记忆／历史 → VLM → target_text的下一个token预测`。目标文本编码后追加真实EOS token；JSONL的`target_text`中不手写`<EOS>`，READ／WRITE生成JSON文本，SUBTASK生成普通文本。loss不会把JSONL元数据整体当答案。

该C2200阶段用文本交叉熵训练语言主干18层attention的q/k/v/o LoRA，另有旧任务K/V锚定；视觉塔、动作专家和base参数冻结。这96条没有FM动作监督、FAST动作标签或value目标，不能当作训练动作专家的数据量。

样本中的实际元数据为`motor_labels=false`、`memory_condition_source=authored_teacher_replay_not_policy_rollout`、`label_schedule=offline_sampled_protocol_contexts_not_online_W32`。源`visible_history=[]`经训练collator映射至模型history字段；真实controller却使用字符串，现有数据也未覆盖非空历史。该输入一致性缺口与动态覆盖不足另见[[2026-10-19-RM65B-C2200留出绑定与仿真闭环验证#历史输入覆盖与一致性缺口|冻结验证]]。
