# 面向机器人接触的动态药瓶组件

核查日期：2026-10-22。实现：`robot_cap_assembly.py`；证据：`cap_component_probes/component_summary.json`。它是独立后续组件，**没有接入或改动已经成功的空瓶抓起放回任务**。

## 本次完成与尚未完成

已构建动态瓶身、动态分离瓶盖与12颗独立胶囊刚体，保留上一轮冻结模型的尺寸、碰撞构造、质量、接触参数及螺距数值。旧包与旧参数文件没有改动。旧 `LabBottle` 的 kinematic 瓶身、角度目标电机、释放后 world cap holder 均不沿用。

实际CPU PhysX负控在1 ms与RealMan现用4 ms两种物理步长下，各用3个种子做直立、初始倒置两种条件，每例6秒，共12例：均未自行解锁，药片中心越界计数均为0。另用明确声明的组件外扰探针验证径向/倾斜导向。**这些不是机器人开盖、机器人倒药、真实螺纹或计量精度验收。**

后续已增加被动紧盖端止挡与载荷相关弹塑性摩擦，当前正式源码SHA为`0785eb4e2a487f4ec4a7c637011e163ceabcce18bbc990fc17980e86b95708d5`。4 ms直立最大转角漂移由0.89684 rad降至0.001137 rad；配对大小外力矩台架测试表明摩擦有有限屈服边界，不会把瓶盖永久锁死。所有D6电机增益与力限仍实际读回为0。

## 最低正确接口

`RobotCapAssembly(scene, pose=..., seed=..., visual=...)` 只在初始化时确定物体状态。创建后通过 `body`、`cap`、`tablets` 取得真实动态对象，物体运动由PhysX、被动约束和外部接触决定。没有 `set_fixture_pose()`、`command_unscrew()` 或独立瓶盖转角目标。

调用方需要在每个**物理步**执行：

```python
assembly.before_step()
scene.step()
assembly.after_step()
```

RealMan的一个60 ms目标包含15个4 ms物理步，因此应把这两个钩子接在未来独立任务的每步 `advance()` 内，不能只在每个动作边界调用一次。此处没有改动当前空瓶任务的 `advance()` 或原时钟。

`make_actor_wrappers()` 为瓶身与瓶盖创建原 RoboTwin `Actor` 包装，使用新metadata中的独立点位与显式质量；可供后续Agent任务读取contact/functional点。`state()` 返回实测相对转角、轴向位移、径向误差和倾角；`try_release()` 只能在实测转角与抬升都达到冻结阈值后移除导向，不改瓶盖pose/速度，也不创建cap holder。松开后盖仍是自由动态物体，机器人必须自己抓住它。

## 螺旋耦合为何不是转盖电机

设实测转角为theta，实测相对抬升为x，螺距为p。取k=p/(2pi)，在啮合区间内约束误差为：

```text
C = x - k * theta
F = force-limited spring-damper reaction on C
tau = -k * F
```

轴向力与对应反作用扭矩分别以相反符号施加给瓶盖和瓶身。它们的功率关系为 `F*x_dot + tau*theta_dot = F*C_dot`，属于沿螺旋约束传递/耗散能量的反力，不是把角度朝某个目标驱动。没有期望转角、没有角度servo、没有与世界固定的瓶盖或瓶身夹具。开盖方向的相对转动必须来自外部机器人接触。

轴向弹簧/阻尼/力限、螺距与释放阈值取自冻结 `physics_spec.json`。旧 angular stiffness/damping/torque limit 原用于角度电机，当前不继续把它们用作转盖执行器；它们的数值另被明确赋给被动微接触/止挡的工程初值，不能据此声称这些新参数已经物理测量。所有D6 drive的线性、twist、swing、slerp增益及力限实际读回为0。

## 被动止挡与摩擦的功率和势能

紧盖端止挡只在实测theta<0时生效。令c=max(-theta,0)，反力矩为 `tau_stop=min(K_seat*c, tau_max)`；theta>=0时严格为0。其势能为小变形的 `V_seat=0.5*K_seat*c^2`，进入力矩饱和后连续转为线性势能。反力满足 `tau_stop=-dV_seat/dtheta`，故功率为 `tau_stop*omega=-dV_seat/dt`。它是单侧机械边界的保守反力，不接受目标开盖角度，也不会在正常开盖区间把盖拉回零角。当前K_seat=0.03 Nm/rad、力矩上限0.02 Nm是明确的待标定工程赋值，数值沿用旧参数，而非真实瓶盖测试结果。

摩擦载荷估计取 `N=max(abs(F_helix), N_axial_contacts)`，其中后者来自瓶身与瓶盖实际PhysX接触冲量沿轴分量除以实际dt。用max避免简单相加造成重复计数。有效半径取冻结瓶身外半径0.025 m；mu_s=0.30、mu_k=0.25沿用旧LabBottle实际创建的物理材料。摩擦上界为 `T_static=mu_s*r*N` 与 `T_dynamic=mu_k*r*N`，没有无依据的固定巨大锁盖力矩。

在这个简化轴向载荷模型中，载荷沿螺旋产生的力矩量级为`k*N`，摩擦界限为`mu*r*N`。冻结几何给出`k/r≈0.0306`，小于mu_k=0.25，因此小载荷下能够自锁具有明确的量级依据；该判断依赖当前载荷与半径近似，不能直接视作真实瓶盖摩擦系数或开盖扭矩证明。

为保留小载荷下的静摩擦，维护微接触弹性扭转z。它随**实测角增量**更新，在超过载荷相关Coulomb上界时进行塑性滑移投影；微接触参考会随滑移变化，不是一个要求盖转到某位置的目标。弹性势能为 `V_friction=0.5*K_b*z^2`，塑性耗散记为“屈服力矩×塑性角滑移”。法向载荷下降时，微接触储能松弛单独记为非负热损失，不能把不存在的超屈服试算弹簧能量误算成真实摩擦功。

另加速度相关阻尼，取 `D_effective=D/(1+D*dt/I_relative)`；在Coulomb边界内的阻尼修正满足 `tau_damping*omega<=0`。K_b=0.03 Nm/rad、D=0.003 Nms/rad同样只是沿用旧数值的工程初值。瓶盖和瓶身受到大小相同、方向相反的全部反力矩。所有这些法则只存储、传递或耗散接触能量，没有规定下一时刻的开盖角。

日志记录每步的摩擦上界、摩擦功率、微接触势能、塑性耗散、载荷松弛、阻尼耗散、止挡势能和止挡功率。反力在物理步**之前**计算，pose在该步**之后**记录，日志明确保存对应的反力求值角度与时间。现有检查验证了这些局部构成关系和非负耗散；**没有把它扩张为PhysX整个离散系统严格能量守恒或全部数值积分误差均已证明的结论**。

## 同条件对比与大小力矩台架

保留的`two_point_v1_source.py`及原12例负控作为无摩擦/无止挡基线。新版本同条件重跑12例，各6秒，均未自解锁、药片中心越界0：1 ms直立最大转角从约0.09749 rad降至3.64e-5 rad；4 ms直立从约0.89684 rad降至0.001137 rad，降低约99.87%。初始倒置的轴向瞬时压缩仍约2.31 mm，没有为让该数字好看而改碰撞或轴向参数。

另以完全声明的台架外wrench分别对瓶盖、瓶身施加等反绕轴力矩，测试1 ms与4 ms两个步长。0.0002 Nm持续0.2秒仅产生0.00342/0.00365 rad微滑，未进入塑性滑移；0.003 Nm同持续时间产生3.237/3.333 rad转动，进入滑移，摩擦力矩始终不超过当时mu*r*N界限。移除大wrench后再观察0.6秒，角度仍在11.57/11.76 rad，没有被位置servo拉回零；这也不是一个被无限锁死的盖。两例尚未达到释放门槛。

台架外wrench不是机器人手指接触，也没有形成机器人数据集。它只用于证明反力方向、有限摩擦边界与被动止挡没有冒充主动旋盖。正式台架结果是`passive_torque_pair_final/receipt.json`；初版时序断言错误和初版塑性耗散过估的证据与修正说明均保留。

## 不能仅凭API名字认为倾斜约束有效

最初用单个D6的pyramid/cone角限时，无驱动不漏烟测通过，但追加横向力/倾覆力矩后，瓶盖倾斜可达3.09 rad。因此两个初版探针明确失败并保留原源文件与结果，没有用角度电机压平现象。

通过GitHub插件读取的[SAPIEN官方固定源码](https://github.com/haosulab/SAPIEN/blob/788fd0afb009ad48558ff1e51243cb92a1573c73/src/physx/joint_component.cpp)显示：cone/pyramid setter仅设置限值，并未将SWING轴从FREE切换到LIMITED。该固定提交与本机二进制的精确编译对应关系未证明，但本机CPU实际现象一致。

当前改为沿瓶盖裙深分开的两个同轴D6径向轴承点。每个点只锁径向Y/Z，轴向X及所有转动均保持free；两个同轴点通过几何关系共同限制倾斜，同时允许沿轴滑动和绕轴旋转。两点间距直接取冻结cap.skirt_depth_m，没有新增角度目标或任意倾斜弹簧。

同一组件外扰探针施加0.1 N横向力与0.001 Nm非开盖轴倾覆力矩，瓶身承受等反力。修复后最大径向误差1.56微米、最大倾角约8.46e-5 rad，探针通过。**这个外扰仅是声明的组件约束测试，不是机器人抓持，也没有用直接施加开盖力矩冒充手扭成功。**

## 必须保留的限制

当前已建被动止挡和摩擦**近似**，但没有真实螺纹接触、交叉螺纹或安全盖机构。旧版0.897 rad拧紧漂移已改善，但4 ms仍有约0.00114 rad短暂转角偏差，轴向偏差小于0.45 mm；初始倒置的最大轴向压缩约2.31 mm。不能把结果描述为瓶盖姿态完全静止或真实旋盖力矩已校准。

药片“不漏”的验收采用实测中心是否离开声明容腔的烟测判据，没有覆盖全胶囊几何严密包含、暴力轴向拉盖、外部撞击、长时间压力或真实液密性。有限力螺旋近似不能代替真实螺纹抗拔能力。

因此当前状态是**被动动态接口与组件负控已验收，完整机器人旋盖任务尚未验证**。后续至少需要独立实现并验证双手分别稳住瓶身与抓盖、接触产生相对开盖转动、实测释放、自由盖移开、机器人倾倒与药片落入容器。新增止挡、微接触刚度、阻尼和法向载荷估计仍需标定，不能直接对瓶盖添加旋转目标电机来声称这些步骤成功。

## 复现与证据

当前正式组件负控组为 `cap_component_probes/passive_friction_final/`，每个receipt记录实际执行的组件SHA、冻结输入SHA、动态状态、全部drive参数读回、种子、时间步和完整trace压缩文件。`two_point_v1/`为无摩擦/止挡的对比基线；旧 `upright/`、`inverted/`、`source_audited_v1/` 为早期弱烟测历史，不能单独证明倾斜约束有效。

`probe_constraint_modes.json` 与 `probe_constraint_modes_cone.json` 保留失败；`probe_constraint_modes_passive_final.json` 是当前版本导向的同条件实际CPU验证，径向最大约1.65微米、倾角最大8.52e-5 rad。汇总与前后对比见`passive_final_summary.json`。整个子项未使用GPU，未修改旧冻结资产、现有SDK24专家或已通过的空瓶任务。

## 完整释放台架补验（仍非机器人示范）

`probe_passive_full_release.py` 对同一冻结源码做CPU外力矩台架：等反0.003Nm作用于动态瓶盖和瓶身，达到实测释放即撤力；没有姿态驱动或释放后holder。1ms与4ms两例施力均约0.44秒，释放时转角15.678／15.892rad、抬升11.739／11.901mm。撤力后0.75秒观察到自由盖掉落。这补齐了前述0.2秒大小力矩台架未跨过释放门槛的覆盖，原结果保留不改。

当前来源SHA仍为`0785eb4e2a487f4ec4a7c637011e163ceabcce18bbc990fc17980e86b95708d5`。新结果在`cap_component_probes/passive_full_release_v1/receipt.json`及两份dt trace；**robot_present=false、usable_robot_demonstration=false**。它不补足双手实际接触、抓盖保持、移盖与倒药的验收。机器人原90mm瓶抓持试验碰到了盖且角速度／位姿积分不一致，另见`robot_cap_task/independent_failure_audit.md`，不能拿本台架覆盖这一失败。
