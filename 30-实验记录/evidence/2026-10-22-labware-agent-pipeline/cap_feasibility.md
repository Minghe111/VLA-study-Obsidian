# RM65-B 闭盖瓶抓持的 CPU 几何筛选

> [!warning] 证据边界
> 本记录使用独立 CPU 碰撞克隆做静态 FK、IK 和离散手指闭合检查。没有创建 renderer，没有推进物理仿真，没有写入运行任务的姿态，没有执行机器人旋盖或倒药。IK 有解、FCL 几何筛选及尺寸反事实都不代表物理抓持成功。

## 几何来源与当前参考

- 机器人是官方工作区的 RM65-B / Inspire Gen4 原碰撞模型，93 个 link、36 个活动关节；SDK24 顺序保持 `[左臂6,左手6,右臂6,右手6]`。
- 独立派生 URDF 仅移除 93 个 visual，保留关节、碰撞、质量、惯量与限位；用途是避免 CPU 几何检查初始化 Vulkan。没有改机器人源文件。
- 以 `robot_cap_task/closed_cap_pick_probes/closed_filled_preclose_q36_diagnostic/measured_preclose_q36.json` 为当前唯一几何参考。该文件来自真实重放 v2 的前 205 个 SDK24 target，停在闭指之前，记录 actual q36、真实 root/palm/body/cap 矩阵。
- CPU 克隆的右掌 FK 与该真实快照的位置误差为 **0.341 μm**、姿态误差 **8.68×10⁻⁷ rad**。这是 FK 对齐验证，不是运动执行验证。
- 对未来闭指的几何候选，使用冻结的 SDK 通道映射和 mimic 耦合计算目标关节位置。不能据此预测接触后的实际指节挠动。
- 原瓶高 **90 mm**、外径 **50 mm**；盖外径 **60 mm**。盖裙向下 12 mm，顶部 4 mm 厚圆盘以原点居中，因此当前实际碰撞总高为 **14 mm**（Z 范围约 `[-12,+2] mm`），而不是把 12+4 直接相加。
- 最终被动组件 `robot_cap_assembly.py` SHA256 保持 `0785eb4e2a487f4ec4a7c637011e163ceabcce18bbc990fc17980e86b95708d5`，未修改。

## 原尺寸下先抓瓶身：未找到可用候选

真实 preclose 姿态下，掌部离桌净空约 **14.53 mm**。闭指后用于夹持的拇指、食指传感器碰撞几何中心约在瓶底以上 **86–88 mm**；闭盖裙的下边缘约在 **81 mm**。因此沿用空瓶抓法会先夹盖，而不先形成瓶身的对向接触。

这与 v2 的实际失败时序一致：独立审计发现第一次碰盖发生在闭指阶段，涉及 `r_inspire_right_index_2` 与 `r_inspire_right_thumb_4`；真实执行未建立瓶身拇指与其他手指的对向抓持。几何结果仅解释这一失败，不替代实际接触记录。

### 预弯手指后降低抓位

`q36_prebend800/right_sweep.json` 与 `q36_prebend750/right_sweep.json` 各检查 9 个掌部下降量，每个 21 个闭指采样。预弯手指 SDK 为 `[0,0,800,800,800,0]` 或 `[0,0,750,750,750,0]`，再闭至原 `[0,0,608,610,610,0]`。

| 沿瓶轴下降 | 闭指过程中的主要阻塞 |
|---|---|
| 0–10 mm | 食指先碰瓶盖，随后才接近瓶身 |
| 15–20 mm | 仍可能碰盖，同时掌部开始碰桌 |
| 25–40 mm | 可避开瓶盖，但预弯初态就有掌部/小指碰桌 |

因此不能把“下移 25 mm”直接发给物理任务尝试；它消除了盖干涉，却引入桌面干涉。

### 围绕抓持中心改变掌部朝向

`q36_right_family800/right_family.json` 额外检查 **36 个**姿态：绕掌部前向轴转动 `[-60,-45,-30,-15,0,15]°`，并把预期接触中心降低 `[10,15,20,25,30,35] mm`。所有 36 个右臂端点 IK 均满足限位，但没有候选能在整个离散闭指前缀中同时满足：

1. 与盖和桌面保持至少 1 mm 净空；
2. 拇指与食指/中指同时到达瓶身 1 mm 范围；
3. 掌部、无关手指不侵入瓶身。

这只是对明确有限姿态族的否定结果，**不能推出所有 90 mm 瓶身抓法都不可行**。

## 尺寸反事实：用于决定是否建立新派生瓶体

只在 CPU 克隆中假设延长直壁，同时把闭盖轴向位置等量提高；外径、手姿态和桌面不变。没有生成或覆盖新资产，没有修改冻结 spec、质量、惯量或物理组件。

| 假设增加瓶高 | 瓶高 | 原预弯闭指轨迹结果 |
|---|---|---|
| 10 / 15 / 20 mm | 100 / 105 / 110 mm | 仍先碰盖 |
| 25 mm | 115 mm | 离散闭指中可避盖/桌，拇指与其他手指同时接近瓶身；该采样盖净空约 9.64 mm、桌净空约 14.53 mm |
| 30 mm | 120 mm | 同一几何条件成立，盖净空约 14.62 mm |

对应证据目录为 `cap_geometry_probes/q36_height_extra_10mm/` 至 `q36_height_extra_30mm/`。

**115 mm 是本次 5 mm 有限网格和现有抓姿中的最小已测可用高度，不是全局最小高度，也不是物理成功。** 如果采用此备选，需要 root 决定建立独立派生模型，重新处理真实碰撞、外观、功能点、质量/惯量假设、组件负控与机器人接触闭环；不能暗改原 90 mm 瓶。

### 已建立的独立 115 mm 实现：静态审查通过

root 随后选择了此备选，由任务 agent 在 `robot_cap_task/profiles/bottle115/` 建立独立 profile。`cap_geometry_probes/profile115_construction_audit.json` 已实际在 CPU 构造其组件与官方 Actor wrapper，**16 项静态/构造检查通过**：

- 原数值配置仅把瓶壁高度改为 115 mm、闭盖位置改为 118 mm；其余螺旋、摩擦、物理、药片数值保留。
- 新 visual 的 bounds 与新尺寸一致；实际构造的碰撞瓶高为 115 mm，盖局部 Z 为 `[-12,+2] mm`，闭盖相对 Z 为 118 mm。
- 实际 body 为 80 g、cap 为 12 g，12 颗独立药片；这些质量仍是声明的工程假设。
- 官方 Actor 实际读取 opening、floor、rim、新 bottom 功能点的矩阵变换正确，抓持参考点仍为 45 mm。
- 旧 90 mm 网格三角面、旧 rim 表面点、旧 hollow sphere-drop 结论已从当前验证字段移到明确的历史参考，当前 profile 没有冒用旧物理通过标记。
- 输入 SHA 在审查期间保持不变，原 `0785…` 组件未修改。

该检查 **没有创建 renderer、没有推进物理步**。实际视觉绑定、闭盖不漏、机器人夹持/抬升/旋盖/倒药仍须由后续真实 rollout 分别验证。

## 原尺寸的下一条单一备选

root 提出可先抓住仍拧紧的瓶盖并提起整瓶，再由另一手在离桌足够高处夹瓶身，最后旋盖。它避开了先抓瓶身时的桌面高度冲突，值得先做有界几何筛选。

已在 `q36_cap_first_local/cap_first.json` 检查 **315 个**局部静态组合：掌部前移 `[0,5,10] mm`、抬高 `[5,10,15] mm`，食指 SDK `[700,725,750,775,800]`、拇指 SDK `[650,675,700,725,750,775,800]`，中指收折。

249 个端点避开瓶身、桌面和无关指碰盖，但没有端点同时满足 **侧向接触法线对向**与**最大接触穿透不超过 1.5 mm**。一些端点虽双指都与盖相交，却是深穿透或接触方向不对，不能作为夹盖成功。该有限族结果不足以否定其他 cap-first 抓法；当前不扩大搜索阻塞已经给出几何依据的 115 mm 派生方案。

目前没有该策略的机器人通过证据，也没有 2.5 圈多次重抓、脱盖后持盖、或倒出 12 片入培养皿的成功证据。不能用组件台架外加力矩探针替代这些机器人操作。

## 保留的历史负控

最早 `summary.json` / `candidates.json` 的 512 姿态、`expanded_same_hold/` 的 1536 姿态以及 `raised_centered_hold_v2/` 的 1536 姿态，使用的是空瓶 v6 measured SDK24 + 按 vendor 耦合重建的 mimic，盖为几何添加。它们保留为探索失败证据，**不再作为当前闭盖可行性依据**。右手实际 q36 的新证据优先。

其中左手曾有少量 IK/无禁止碰撞端点，但有指尖悬空或意图接触的深穿透；进一步有限手指扫描未得到浅层对向夹盖。因此没有把这些端点发布成可执行夹盖动作。

## 复核入口

源码：`robot_cap_task/cap_grasp_probe.py`；各 `right_sweep.json`、`right_family.json` 内包含输入文件 SHA256、机器人/资产 SHA256、全量参数、SDK24 候选和失败采样。

给任务实现者的 115 mm 唯一候选在 `cap_geometry_probes/geometry115_candidate.json`：原掌姿保持，预弯 SDK800；几何首次双侧近瓶身样本为 `[0,0,627.2,629,629,0]`，含 full q36、SDK24、body→palm 完整变换及来源 SHA。它是几何近接目标，**物理执行必须依据接触反馈停止闭指**，不能把 SDK629 当通用力闭合参数。

所有脚本写入仅限本轮独立 `cap_geometry_probes/`。FK 克隆使用 `set_qpos` 是静态几何计算；没有向工作任务写 pose、施加额外 wrench、启用盖旋转电机或使用夹具。

## 左手夹盖：内在几何构造与首次接触边界

`robot_cap_task/left_cap_intrinsic.py` 从原 thumb/index 碰撞网格提取掌内表面位置、法线与 SDK 耦合关节，不以原瓶身抓取掌姿作局部平移。把两个候选接触点之间的线对齐盖的水平直径、其中点放在盖局部 Z=-5 mm，即可在构造上消除两点高度差。绕该水平线的 roll 与绕盖轴的 yaw 留给后续 IK/全模型碰撞筛选。

`left_intrinsic_exposed_final/` 是当前严格网格版本；其初始 FK 与 4 组非零手指 SDK 的实际 CPU articulation FK 分别核对，最大位置误差约 0.711 μm。原 14 mm 盖未放大。该手内构造本身没有右手或持瓶高度假设。

> [!important] sensor 表面不是夹持的必要条件
> 内在 sensor 表面仅用于提供有根据的手势种子。父指节的真实碰撞体覆盖某 sensor 面，并不表示机器人手指不能接触物体。后续检查必须使用完整 thumb/index 父 link 与 sensor 的真实碰撞，不要求接触一定落在 sensor，也不要求法线完全水平。

严格表面种子中，粗网格只有 4 对满足 60–66 mm 间距、两侧朝向余弦≥0.7、法线点积≤-0.7，去相似后保留 2 个。其最小掌部环绕半径约 91.9 mm，不应描述成轻松的小半径夹持。早期 `left_intrinsic/`、`left_intrinsic_small_orbit/` 曾使用 0.5 mm 表面暴露探测偏移，已保留为探索历史，当前不据此声称可靠可夹持。

`left_cap_held_probe.py` 先用 v2 真实 airborne 快照做 216 个内在 yaw/roll 端点，51 个 IK 有解，17 个避开禁止碰撞，但最终闭指目标没有得到可信的浅层对向接触。随后参考切换到 v3 `actual_terminal_snapshot.json`，其实际 q36、root、body、cap 矩阵均来自真实机器人驱动仿真。v3 参考仍处于运动中的 lift 末端，不是静止刚性附着参考。

不能只看最终闭指目标的相交深度来排除力控抓持：`left_cap_closing_prefix.py` 进一步从张开/预弯姿态分别闭合 index 与 thumb opposition，记录完整父 link 的首次接触次序，遇力应停止的真实 PhysX 探针才是后续验证。

FCL 的 compound convex EPA 深度在本轮出现了明显不一致：从无碰撞到首次接触的 10-SDK 小步，报告的深度可达 10–15 mm，超过该小步可能的全部网格顶点位移。因此保留原深度作为诊断字段，不直接当作真实穿透距离。新候选以无接触/有接触 SDK 区间二分，并计算两个区间端点之间实际移动顶点的最大位移上界；这一界依赖 FCL 的碰撞布尔判定，仍不是独立 PhysX 接触验证。

首次接触候选不等于摩擦力闭合、不等于实际夹稳。实际 probe 仍应采用 60 ms 低速 SDK24、分别依据 index/thumb 的真实力反馈止闭、限制瓶身/右手/桌面禁碰与异常盖力。若仅有端点候选，不得宣称 45–90°扭盖弧线可行；绕盖轴旋转需要掌部同时产生环绕位移，并跟随实测轴向抬升，不能用原地转 wrist 或刚性附着假设替代。

### 已交付的唯一首次接触探针提案

`cap_geometry_probes/left_cap_first_contact_probe_candidate.json` 选择了 v3 几何参考下的 trial12 / endpoint38。掌部环绕半径约 119.9 mm，张开姿态为 `[0,0,0,1000,1000,1000]`。

1. 先单独闭食指。FCL 首次接触区间为 SDK `560.107421875`（无接触）到 `560.09765625`（接触），预期父 link 为 `l_inspire_left_index_2`。
2. 食指停在实际测力止闭位置，再单独改变拇指 opposition。几何首次区间为 SDK `348.45703125`（无接触）到 `348.4375`（接触），预期父 link 为 `l_inspire_left_thumb_4`；拇指 flex 保持 1000。

两个二分区间的实际移动网格顶点上界约为 1.96 / 2.21 μm。该结论依赖 FCL 碰撞布尔判定；FCL EPA 法线点积约 +0.45，**没有几何力闭合证明**。它是交给低速限力 PhysX 探针的首次接触提案，不是“已夹稳”结果。历史 `closing_trials.json` 中 `geometric_pinch_candidate` 标志仅表示当时选出的探针提案，其同条 scope 与本说明为准；后续源码已更名为 `first_contact_probe_proposal`。

提案包含完整 cap→palm 变换、q36/SDK24、开放姿态禁碰净空与全部输入 SHA。它引用运动中的 v3 快照；执行前必须用当前真正静持参考重新绑定 `T_world_palm=T_world_cap·T_cap_palm`、重新 IK 和全碰撞检查，并以真实力反馈止闭，不能直接执行旧世界坐标或原深闭合种子 SDK520/opp150。

### 已重绑实际静持参考，thumb opposition400 可作开放端点

`left115_static_rebind400/rebind.json` 使用 `static_hold_probes/held115_static_reference_v1/actual_terminal_snapshot.json` 重新核对原掌内提案。该真实参考存在已披露的右食指轻触盖，不把它错误地视为新发生的左手禁碰，也不要求右手对盖的接触为零。

- 张开/预弯 SDK `[0,0,0,1000,1000,400]` 的掌部端点通过 CPU 全禁止碰撞检查：拇指到盖约 6.70 mm，左手到瓶身约 12.44 mm、到右手约 11.48 mm。
- 在 home 设置该手势的 41 个离散采样均 clear。
- 重绑后世界掌位置为 `[0.085004903,-0.231391325,1.017296327] m`；旋转矩阵、left arm6、q36 完整记录在 JSON。
- 单独闭指的首次接触约为 index SDK560.10、thumb opposition SDK348.443。仍无真实夹持/力闭合结果。
- 直接从 home 作关节直线插值会在约 49% 时使食指碰桌；9 个简单 via 顺序也未通过，因此未把它们下发执行。

`left115_static_rrt_fast_v2/candidate_plan.json` 随后找到 **108 行 left-arm6** 的有限 RRT polyline，并在 **4599 个**保守顶点位移间隔≤1 mm 的采样点，以原生规划碰撞 predicate 复核无禁止碰撞。规划约 1.27 s、合计约 10.79 s。该密集复核与规划共享 FCL 几何和明确的规划 ACM，**不是独立实现或连续 gap 证书**，也没有测得路径最小净空；报告中的该字段为 `null`。

规划角色只忽略固定右手在该实际 q36 下对 body/cap 已存在的 FCL proxy overlap，并逐对记录；不等于宣称每一对都有非零 PhysX 力，不改物理 mask，不把瓶永久刚附。左手对瓶身、瓶盖、右手、桌面及 self 的禁碰仍保留。任务实现者还须在真实持握/左手准备后的当前场景中重绑、复核整条路径并按 60 ms 限速执行。

几何 JSON 的 full SDK24 包含静态右侧测量值，不能整体当 drive 命令。实际应只取 left arm6/left SDK6，右侧继续沿用现有保持/测力反馈。
