# 本周工作汇报：RoboTwin与LingBot-VLA 2.0

**周期：2026年9月14日—9月20日。** 本周可追溯工作主要集中于9月18—20日。汇总依据为研究笔记、源码核查及已归档部署验收记录；本次编写周报未重新登录服务器跑测试。

## 一、本周进展概述

本周围绕“基于语言约束与强化学习提升双臂机器人操作能力”的研究目标，完成了模型与实验平台选型、RoboTwin及LingBot-VLA基础环境建设、默认训练推理流程梳理，并建立了可持续维护的研究笔记与硬件资源档案。

当前以 **LingBot-VLA 2.0作为主模型、RoboTwin作为仿真验证平台、睿尔曼RM65-B双臂灵巧手作为后续真机对象**。环境工作已推进到依赖、通信及部分模型分支验收；尚未完成完整训练、闭环仿真成功率复现或真机实验，因此本周产出以研究方案、接口理解和部署基础为主。

## 二、已完成的工作

### 1. 明确模型、平台与硬件路线

调研RoboTwin、RoboDojo、RoboChallenge、RoboCasa365等评测平台，明确仿真与真机、单任务与多任务、不同数据量和评测协议之间的区别。将RoboTwin作为近期双臂实验主平台，真机评测平台作为后续参考。

模型层面，以LingBot-VLA 2.0为主要研究对象，计划以π0.5、SmolVLA和ACT形成强VLA、轻量VLA与基础模仿学习对照。π0与SmolVLA的架构分析用于理解技术演进；这不意味着已经完成上述基线训练。

修正了最初对本体的认识：实际机械臂是RM65-B，每臂6轴，末端为双灵巧手，相机为头部与左右腕共3台D435。灵巧手实物型号和独立控制自由度仍待最终确认，不能直接使用RoboTwin的双夹爪动作接口。

### 2. RoboTwin环境搭建与核验

在本地创建独立`robotwin`环境，完成基础依赖安装与导入检查，处理了下载链路波动及SAPIEN依赖的setuptools兼容问题。随后对166服务器进行了只读核验，确认远端RoboTwin仓库、资产目录及环境存在。

远端`robotwin`的Python为3.10.21，PyTorch为2.4.1+cu121，环境内nvcc为12.1；PyTorch能识别8张RTX 3090。核对了SAPIEN、MPLib、PyTorch3D、CuRobo和XPolicyLab的安装版本，并记录父仓库与子模块commit。

该阶段验证了环境版本与CUDA可见性，未据包安装记录推断渲染、规划、资产完整性或任务rollout已经通过。

### 3. LingBot环境修复、权重迁移与组件验收

根据9月19日本地修复记录，保留Python 3.12、PyTorch 2.8.0+cu128与FlashAttention 2.8.3，修复NumPy、视频解码、深度模块与训练入口相关依赖。核心requirements的44项版本全部匹配；本地12项组件检查通过，包括GPU小规模前反向、视频编解码和训练/部署入口导入。

根据9月20日161服务器部署记录，已同步源码、迁移Conda环境并核验权重。针对Ubuntu 20.04的GLIBC兼容问题，在目标A6000服务器重新构建FlashAttention并修复相关二进制依赖。主要验收包括：

- 8卡NCCL all-reduce通过，rank 0—7结果均为36。
- 44项核心依赖版本匹配，12项组件检查通过。
- 23个同步文件SHA-256校验一致，另行补齐MoGe教师权重。
- 真实MoGe＋LingBot-Depth、DINO-Video教师分支单批前向通过，输出为有限值。

这些结果说明环境、权重与关键组件已有部署证据；**尚未执行完整学生模型前反向、训练step或RoboTwin评测**。基础预训练权重也不等于RoboTwin后训练checkpoint。仍保留11项上游依赖声明冲突，不能将组件通过表述为所有功能均兼容。

### 4. 梳理默认数据、训练与推理流程

通过配置文件和实际代码路径，整理了两个框架的职责及默认行为：

| 基本问题 | 本周确认的结论 |
| --- | --- |
| 框架分工 | RoboTwin负责仿真、示范与评测；LingBot负责策略训练与动作生成 |
| 数据格式 | 当前RoboTwin原生采集为XPolicyLab HDF5；LingBot示例消费LeRobot数据，二者之间需要正确转换 |
| 输入 | 当前三路RGB、语言任务、当前机器人状态 |
| 输出 | 默认50步动作块；RoboTwin有效执行量为12维关节角＋2维夹爪位置 |
| 动作语义 | 默认绝对关节位置，不是末端位姿或关节速度命令 |
| 微调范围 | 当前RoboTwin配置对主策略全量微调；MoE稀疏激活不等于仅微调固定专家 |
| 训练方法 | Flow Matching动作监督，叠加当前/未来特征蒸馏；默认不包含RL |
| 推理循环 | 同步请求动作块，执行后再观测；多任务并行不等于单机器人异步控制 |
| 语言机制 | 指令token进入VLM；默认在线流程不先输出子任务列表。离线数据制作包含子任务切分与语言标注 |

此外，整理了RoboTwin的50项任务及clean/randomized设置。发现LingBot附带指南固定的RoboTwin revision与当前XPolicyLab版RoboTwin不同，旧数据转换及评测接口不能直接假设兼容。

### 5. 完成模型架构比较与知识整理

对照π0、SmolVLA与LingBot-VLA 2.0，明确三者均采用视觉语言条件下的连续动作生成，LingBot 2.0主要扩展为动作FFN内的稀疏MoE、当前/未来双query特征蒸馏，以及覆盖灵巧手、腰、头与底盘的55维统一表示。

区分了“训练时预测未来特征”和“部署时生成未来视频/显式规划”，避免将LingBot-VLA 2.0误解为完整视频世界模型或在线任务分解器。

Obsidian中已建立研究主题、模型、实验、硬件资源、环境部署和模板目录，新增项目概述、默认流程对照、架构比较及服务器资源卡。记录commit、来源日期和验证范围，使后续实验能够追溯配置与证据。

## 四、我们希望开展的研究

### 研究问题

在已有VLA具备基础操作能力后，重点研究：**能否通过语言约束和RL后训练，使策略不仅完成任务，还按指定目标、手臂分工和动作顺序完成，并降低约束违背？**

例如，在同一场景中改变“取哪个物体”“使用哪只手”“先做什么”“不能碰什么”，检查策略是否真正利用语言，而非仅依赖视觉场景和训练中的固定动作套路。

### 拟开展的实验路线

1. **建立可复现基线**：先打通RoboTwin与LingBot的版本、数据和评测接口，复现一个任务的完整动作闭环，再扩展到小任务集。
2. **构建语言约束评测**：固定场景与操作目标，控制性改变目标对象、左右手分工、顺序及禁止接触对象；划分未见措辞、对象或场景。
3. **研究RL后训练**：从同一SFT checkpoint出发，对比SFT、SFT＋RL、SFT＋语言约束、SFT＋RL＋语言约束。语言约束的具体实现和RL算法尚待确定，不预先宣称某种奖励或结构有效。
4. **迁移至RM65-B**：在共同数据与执行接口稳定后，开展双臂双灵巧手适配，先固定底盘等额外机构，验证小规模任务，再增加复杂度。

公平比较要求统一示范数据、任务划分、交互预算及种子，并记录训练模块、精度、教师开关和动作约定。指标同时包含任务完成率、约束违背率、人工干预率及推理/执行延迟。ACT主要用于基础操作对照，不将其当作等价语言理解模型。

当前研究假设是语言约束与RL可能改善行为可靠性；**本周尚无实验结果证明这一假设**。

## 七、口头汇报简版

本周主要围绕RoboTwin和LingBot-VLA 2.0完成了实验基础建设与研究方案梳理。平台上，核验了8卡3090服务器的RoboTwin环境，并在8卡A6000服务器完成LingBot环境与权重迁移、通信及教师分支验收；目前尚未完成完整训练和闭环成功率复现。调研上，梳理了数据格式、三视角输入、关节动作块输出、全量微调和同步推理流程，并明确了LingBot相对π0、SmolVLA的MoE与未来特征监督设计。下一步先解决版本和数据接口问题，完成单步训练及单任务仿真闭环；在此基础上开展语言约束与RL后训练对照，最终适配RM65-B双臂灵巧手平台，重点评估任务完成率和语言约束违背率。
